# ABC 项目目录结构设计

- 日期：2026-10-01
- 状态：已确认（方案 B：按功能分文件夹）
- 引擎：Godot 4（标准版，GDScript）

## 背景

家长要和孩子在 `D:\myclass\myGames\ABC` 从零开始做一个游戏（暂定名 ABC）。
玩法尚未确定，因此本设计只约束"项目骨架"，不涉及具体玩法内容。
结构需适配任意 2D 小型游戏：确定玩法后只往里加内容，不需要动结构。

## 备选方案

| 方案 | 组织方式 | 结论 |
|---|---|---|
| A 按文件类型分 | 所有场景进 `scenes/`，所有脚本进 `scripts/` | 教程常见，但同一个角色的文件分散在两处，孩子不好找，Godot 官方也不推荐 |
| B 按功能分 | 每个功能（玩家/敌人/关卡/界面）一个文件夹，场景和脚本放一起 | ✅ 采用。Godot 官方最佳实践，符合孩子"一个角色一个家"的直觉 |
| C 极简扁平 | 全部文件放根目录 | 零负担但文件超过十个就乱，不可扩展 |

## 最终结构

```
ABC/
├─ project.godot      Godot 项目文件（用 Godot 的"导入"打开它）
├─ icon.svg           游戏图标
├─ .gitignore         忽略 Godot 缓存与导出产物
├─ README.md          项目说明 + 文件夹导览
├─ docs/              设计笔记、点子本、孩子的涂鸦扫描
│  └─ superpowers/specs/   正式设计文档（本文件所在处）
├─ player/            玩家角色（场景 + 脚本在一起）
├─ enemies/           敌人
├─ levels/            关卡
├─ ui/                开始菜单、计分、暂停等界面
├─ assets/
│  ├─ art/            图片素材（孩子画的画放这里）
│  ├─ audio/          音效、背景音乐
│  └─ fonts/          字体
└─ addons/            插件（暂时为空，预留）
```

## 关键约定

1. **场景与脚本同目录**：`player/player.tscn` 和 `player/player.gd` 放在一起。
2. **共享素材集中**：被多个功能复用的图片/音频/字体放 `assets/`；只属于某一个功能的小素材也可以直接放那个功能的文件夹里。
3. **命名**：文件名用英文小写 + 下划线（`green_slime.gd`）；中文写在文档和代码注释里。
4. **docs/**：记录设计过程；正式设计文档放 `docs/superpowers/specs/`，随手的点子放 `docs/ideas.md`。
5. **空目录**：用 `.gitkeep` 占位，将来用 git 管理时不丢目录。
6. **.gitignore**：忽略 Godot 自动生成的缓存目录 `.godot/` 和导出成品目录 `export/`。

## 演进方式

- 新敌人 → 在 `enemies/` 里加一组 `xxx.tscn` + `xxx.gd`
- 新关卡 → `levels/level_2.tscn`
- 确定玩法后 → 单独走一次游戏设计头脑风暴，产出玩法设计文档
- 重构信号：某个功能文件夹超过约 10 个文件且混着多种职责时，再往下细分
